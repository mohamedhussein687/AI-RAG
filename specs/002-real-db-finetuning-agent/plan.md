# Implementation Plan: Real Database Fine-Tuning Agent

**Branch**: `feature/real-db-finetuning-agent` | **Date**: 2026-06-23 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/002-real-db-finetuning-agent/spec.md`

## Summary

Extend the existing AI-RAG system into a real database-aware Arabic agent. The feature restores a protected SQL backup outside Git, discovers and indexes project database schema intelligence, generates safe supervised fine-tuning datasets, runs real LoRA/QLoRA-style training where hardware permits, and routes user messages through the AI module as the primary classifier/planner. Live operational facts remain queried from MySQL at runtime using validated structured plans and read-only parameterized execution; model training teaches domain vocabulary, routing, safe planning, refusal, and final Arabic answer behavior rather than memorizing changing rows.

## Technical Context

**Language/Version**: Python 3.11+ for the AI module, ingestion worker, schema discovery, dataset generation, training, evaluation, and MySQL execution; Java 21/Spring Boot remains the public gateway validator/executor boundary where already present.

**Primary Dependencies**: Existing FastAPI/Pydantic v2/httpx/SQLAlchemy/Alembic/qdrant-client stack; add MySQL driver support for restore/discovery/execution, Hugging Face Transformers + PEFT + TRL-compatible training path, dataset validation utilities, YAML config parsing, and existing Spring WebClient/Security/Test support.

**Storage**: Protected SQL backup outside Git; restored MySQL/MariaDB development database for schema discovery and live query smoke tests; PostgreSQL metadata for schema state/training metadata where useful; Qdrant for schema intelligence and long-text/document context; local filesystem paths outside Git for generated real datasets, adapters, checkpoints, logs, and model outputs.

**Testing**: Pytest for AI module, ingestion worker, schema discovery, dataset, validator/compiler/executor, and training smoke tests; Maven tests for Spring Gateway validation/execution boundaries; local smoke commands for restore, schema ingest/status, dataset generation, evaluation, and chat; server smoke tests only after commit/push/pull.

**Target Platform**: Local Linux development workstation first; production/test server at `ssh techlab-ai` under `/home/rag/` only after GitHub push; Docker Compose deployment remains private for internal AI/Qdrant/Postgres/model services.

**Project Type**: Backend AI/RAG service, ingestion/CLI tooling, training pipeline, Spring Gateway integration, and operator documentation.

**Performance Goals**: Schema discovery and dataset generation complete within operator-friendly batch runtime; chat route/planning remains interactive for required smoke prompts; live SQL respects configured row limits and query timeouts; evaluation provides measurable route/planning/refusal quality before model acceptance.

**Constraints**: No secrets, backups, generated real datasets, adapters, model weights, or credentials in Git; no direct server-source edits; no raw SQL generated by the model is executed; sensitive fields are denied; live facts come from MySQL; schema intelligence remains refreshable; all server testing follows commit -> push -> pull.

**Scale/Scope**: Phase covers one restored project database source, schema intelligence, alias-enriched planning, generated SFT dataset, real training/evaluation scripts, smoke serving configuration, and required public/internal chat contracts. It does not replace live SQL with model memory and does not make Qdrant a full mirror of operational rows.

Research completed in [research.md](./research.md). Key decisions:

- Use Qwen-compatible LoRA/QLoRA training through Transformers/PEFT/TRL-style tooling.
