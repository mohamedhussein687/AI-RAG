# Data Model: Server AI RAG Module

## Document

Represents an indexed knowledge item owned by a tenant and optionally scoped to a project.

**Fields**

- `id`: Stable document identifier generated by the AI module.
- `tenant_id`: Required tenant identifier.
- `project_id`: Optional project identifier.
- `title`: Required human-readable title.
- `source_type`: Required category such as `policy`, `manual`, `contract`, `procedure`, or `other`.
- `content_hash`: Hash of submitted content for duplicate detection and audit.
- `access_policy`: Required permission requirements and optional policy metadata.
- `metadata`: Caller-supplied metadata such as version or external reference.
- `status`: `received`, `indexing`, `indexed`, or `failed`.
- `error_message`: Optional indexing failure detail safe for operators.
- `created_at`, `updated_at`, `indexed_at`: Timestamps.

**Relationships**

- Has many `Chunk` records.
- May be referenced by many `KnowledgeSearchResult` entries.

**Validation Rules**

- `tenant_id`, `title`, `source_type`, and non-empty content are required at indexing time.
- `access_policy.permissions` defaults to an empty list only for tenant-visible documents; restricted documents must include explicit permissions.
- `status` becomes `indexed` only after chunk metadata and vector entries are available.

**State Transitions**

```text
received -> indexing -> indexed
received -> indexing -> failed
failed -> indexing -> indexed
```

## Chunk

Represents a searchable excerpt from a document.

**Fields**

- `id`: Stable chunk identifier.
- `document_id`: Parent document identifier.
- `tenant_id`: Copied from parent document for filtering.
- `project_id`: Copied from parent document when present.
- `chunk_index`: Required zero-based order within the document.
- `text`: The chunk text stored in metadata storage for answer context.
- `text_hash`: Hash of chunk text.
- `title`: Parent document title copied for source display.
- `source_type`: Parent document source type copied for filtering.
- `permissions`: Required permissions copied from document access policy.
- `page_number`: Optional page number when available.
- `section_title`: Optional section or heading.
- `vector_id`: Identifier of the corresponding vector entry.
- `created_at`: Timestamp.

**Relationships**

- Belongs to one `Document`.
- Has one vector payload in Qdrant.

**Validation Rules**

- `tenant_id`, `document_id`, `chunk_index`, `text`, `source_type`, and `permissions` are required.
- `text` must be a bounded excerpt, not a full document.
- Payload fields in vector storage must match metadata fields used for authorization.

## Conversation

Represents AI-module metadata for a chat conversation.

**Fields**

- `id`: Conversation identifier supplied by the gateway.
- `tenant_id`: Tenant identifier when supplied by user context.
- `locale`: Preferred locale such as `ar` or `en`.
- `created_at`, `updated_at`: Timestamps.

**Relationships**

- Has many `AgentEvent` records.

**Validation Rules**

- Conversation records do not store construction database credentials or raw SQL.
- Conversation history may be supplied per request; long-term storage is limited to metadata needed for AI-module operation.

## AgentEvent

Represents an auditable decision or final-answer event.

**Fields**

- `id`: Event identifier.
- `request_id`: Request identifier from middleware or caller.
- `conversation_id`: Optional conversation identifier.
- `tenant_id`: Optional tenant identifier.
- `event_type`: `decide`, `final`, `rag_search`, `document_index`, or `health`.
- `status`: `success`, `validation_error`, `forbidden`, `unsupported`, or `failure`.
- `input_summary`: Redacted summary of the request.
- `output_summary`: Redacted summary of the response.
- `created_at`: Timestamp.

**Validation Rules**

- Tokens, credentials, raw SQL, and secrets must not be stored.
- Request IDs are required for protected endpoint events.

## UserContext

Represents caller-provided authorization context used by Server 2.

**Fields**

- `id`: Optional user identifier.
- `tenant_id`: Required for document search and indexing-related authorization checks.
- `project_ids`: Optional list of authorized project identifiers.
- `roles`: Optional role names.
- `permissions`: Required permission list for document access.

**Validation Rules**

- RAG search requires `tenant_id`.
- Project-scoped chunks require matching `project_id` in `project_ids` when `project_ids` is present.
- A chunk with required permissions is returned only when all required permissions are present in `permissions`.

## AllowedSchema

Represents the live data surface the gateway permits the AI module to reference.

**Fields**

- `tables`: List of allowed tables/entities.
- `tables[].name`: Entity name.
- `tables[].columns`: Allowed columns/fields for planning.
- `tables[].allowed_operations`: Optional operation allowlist.

**Validation Rules**

- Tool call plans must reference only supplied tables and columns.
- If the schema is empty, live data questions return unsupported or clarification rather than invented plans.

## ToolCallPlan

Represents a gateway-managed live data lookup request.

**Fields**

- `id`: Caller-visible tool call identifier.
- `tool`: `database_query`.
- `plan.operation`: One of `count`, `list`, `sum`, `avg`, `min`, `max`, or `group_count`.
- `plan.table`: Allowed entity name.
- `plan.column`: Optional allowed field for aggregate operations.
- `plan.filters`: List of structured filters.
- `plan.order_by`: Optional structured ordering.
- `plan.group_by`: Optional allowed field.
- `plan.limit`: Row limit bounded by request rules.

**Validation Rules**

- Raw SQL is never present.
- Joins are omitted unless explicitly allowed by request rules.
- Limits must not exceed caller-provided `max_rows`.

## KnowledgeSearchResult

Represents an authorized, ranked chunk result.

**Fields**

- `chunk_id`: Chunk identifier.
- `document_id`: Document identifier.
- `title`: Document title.
- `source_type`: Document category.
- `project_id`: Optional project identifier.
- `chunk_index`: Chunk order.
- `page_number`: Optional page.
- `section_title`: Optional section.
- `text`: Authorized excerpt.
- `score`: Retrieval or reranking score.

**Validation Rules**

- Returned only after tenant, project, and permission checks pass.
- Text must remain an excerpt and not a full document.

## AgentDecision

Represents `/api/agent/decide` output.

**Variants**

- `final_answer`: Direct answer.
- `clarification`: Question asking for missing information.
- `tool_calls`: One or more tool plans plus optional local RAG results.
- `forbidden`: Refusal for prohibited or unauthorized sensitive requests.
- `unsupported`: Request cannot be handled from available data and tools.

**Validation Rules**

- Exactly one variant is returned.
- JSON must validate before sending.
- Arabic input or locale results in Arabic user-facing text.

## FinalAnswer

Represents `/api/agent/final` output.

**Fields**

- `answer`: User-facing answer.
- `display.type`: `text`, `metric`, `table`, `answer_with_sources`, `mixed`, or `clarification`.
- `display.data`: Structured display payload.
- `sources`: Source list when RAG chunks are used.

**Validation Rules**

- RAG-backed answers include sources.
- Row results use `table`; aggregate results use `metric`; mixed DB and RAG results use `mixed`.
- Missing facts are stated as unavailable rather than invented.
